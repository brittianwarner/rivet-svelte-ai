# Railway infrastructure

`.railway/railway.ts` is the infrastructure source of truth, using the official `railway/iac` SDK. There are no `railway.json` or `railway.toml` files.

It declares two buckets and one image (the root `Dockerfile`), deployed as either:

- `TOPOLOGY = "split"` (default): three services.
  - `app` (`ROLE=web`, public, 2 replicas): pages; forwards `/api` and `/rivet` to `api`. No secrets, no bucket.
  - `api` (`ROLE=api`, private, 2 replicas): actors, `/api`, the `/rivet` relay. App files in the `files` bucket.
  - `engine` (`ROLE=engine`, private, 3 replicas): the Rivet cluster, state in the `rivet-cluster` bucket under `engine/`.
- `TOPOLOGY = "all"`: service `app`, 3 replicas, `ROLE=all`. Every replica is an engine node plus everything else; engine state under `rivet-cluster/`.

The public service is always `app`, so a custom domain survives a topology switch. Switching creates or deletes the other services and starts a fresh cluster on the other prefix: read the plan.

See [the deployment guide](../docs/deployment.md) for roles, rollout windows, rehearsal and load results, and risks.

```sh
railway status --json                 # Confirm project AND environment first
bun run railway:plan                  # Read-only diff, values redacted
railway config plan --out /tmp/railway-plan.json
railway config apply --plan /tmp/railway-plan.json   # a human, after reading every Destroy line
```

**Anything omitted from the file is deleted on apply.** Moving from `all` to `split` deletes the engine, S3 and token variables from `app` (web holds none), and the actor state of the old cluster stays under `rivet-cluster/` without moving. Export what you need first, and apply only with explicit authorization. Never add `--confirm-destructive` to automation.

Rules that keep the cluster safe:

- Keep `engine` at `overlapSeconds: 120` and `drainingSeconds: 660`. Deploys replace every engine node; shorter windows lost quorum permanently in rehearsal. `api` and `app` are stateless (30 / 120).
- Keep the bucket endpoints https (Railway buckets are). The engine's S3 client does not speak plain http.
- Only port 8080 on `app` gets a domain. Never expose `api`, api_peer (6421), Guard (6420) or metrics.
- `RIVET_TOKEN` and `ENTITY_SECRET` are generated by Railway (`secret(64)`). Do not use `ctx.randomString()` for secrets: it is deterministic.
- Two clusters must never share one bucket prefix. The engine never reads the `files` bucket, and the api never writes the engine's.

Keep plan artifacts out of Git. Inspect `--json` apply status and verify the resulting service instances; a successful CLI exit alone does not prove the environment applied. `railway config pull` imports an existing project with secrets preserved; do not use `--include-variables`, `--decrypt-variables`, or `--show-values` in agent logs.

Custom domains attach once through Railway, then move into the file. Generated Railway domains are managed with `railway domain` and are not authored in IaC.
