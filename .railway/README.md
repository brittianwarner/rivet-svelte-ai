# Railway infrastructure

`.railway/railway.ts` is the infrastructure source of truth, using the official `railway/iac` SDK. There are no `railway.json` or `railway.toml` files.

It declares one bucket and one image (the root `Dockerfile`), deployed as either:

- `TOPOLOGY = "all"` (default): service `app`, 3 replicas, `ROLE=all`. Every replica is an engine node plus the app.
- `TOPOLOGY = "split"`: service `engine` (`ROLE=engine`, 3 replicas, private) plus service `app` (`ROLE=app`, scales freely).
- `TOPOLOGY = "tiers"`: `engine` plus `runner` (`ROLE=runner`, private) plus `app` (`ROLE=front`, public). Runners and the front scale independently.

The public service is always `app`, so a custom domain survives a topology switch. Switching still deletes and creates the other services: read the plan.

See [the deployment guide](../docs/deployment.md) for roles, rollout windows, rehearsal results, and risks.

```sh
railway status --json                 # Confirm project AND environment first
bun run railway:plan                  # Read-only diff, values redacted
railway config plan --out /tmp/railway-plan.json
railway config apply --plan /tmp/railway-plan.json   # a human, after reading every Destroy line
```

**Anything omitted from the file is deleted on apply.** On a project that still has the old layout, the plan destroys the `rivet`, `api` and `web` services and the `rivet-log` volume. The old engine's actor state does not move to the new cluster (`S3_PREFIX=rivet-cluster/`). Export what you need first, and apply only with explicit authorization. Never add `--confirm-destructive` to automation.

Rules that keep the cluster safe:

- Keep `overlapSeconds: 120` and `drainingSeconds: 660`. Deploys replace every engine node; shorter windows lost quorum permanently in rehearsal.
- Keep the bucket endpoint https (Railway buckets are). The engine's S3 client does not speak plain http.
- Only port 8080 on `app` gets a domain. Never expose api_peer (6421), Guard (6420) or metrics.
- `RIVET_TOKEN` and `ENTITY_SECRET` are generated by Railway (`secret(64)`). Do not use `ctx.randomString()` for secrets: it is deterministic.
- Two clusters must never share one bucket prefix.

Keep plan artifacts out of Git. Inspect `--json` apply status and verify the resulting service instances; a successful CLI exit alone does not prove the environment applied. `railway config pull` imports an existing project with secrets preserved; do not use `--include-variables`, `--decrypt-variables`, or `--show-values` in agent logs.

Custom domains attach once through Railway, then move into the file. Generated Railway domains are managed with `railway domain` and are not authored in IaC.
